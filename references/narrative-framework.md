# 六大叙事范式与研究论证框架

六大范式不是论文类型，也不是投稿模板。它们回答的是六种不同的“研究价值从哪里来”：机制解释、默认设定的重构、形式化保证、失效的测量、真实世界的约束、以及统一性与简洁性。一篇论文可以有多个标签，但应有一条主线能把问题、方法和证据串起来。

## 先画一张故事图

先串起最短的论证链，每个箭头都应能在正文中找到证据或明确的假设：

```text
研究问题/现象 → 本文贡献 → 支持证据 → 成立范围

机制研究可展开为：现象 → 机制假设 → 区分预测 → 干预与对照
理论研究可展开为：形式问题 → 定义与假设 → 定理/构造 → 证明与边界
基准研究可展开为：测量缺口 → 任务与指标 → 有效性检验 → 发现与范围
```

“我们提出一个模块，指标提升了”可以支持方法改进；若进一步声称解释了机制，就需要能区分替代解释的证据。工程权衡、理论结果和可靠的负结果都可形成贡献，不必强行补一个根因故事，也不能由叙事类型预测奖项。

## 六种范式的诊断卡

下列证据包按实际主张选用。它们帮助定位缺口，不要求每篇论文完成所有项目；缺一类证据时先判断对应主张是否需要保留。

### 1. 根因手术刀（root-cause scalpel）

**核心问题**：现有方法在什么条件下翻车，真正的限制因素是什么？

**典型链条**：稳定现象 → 机制假设 → 诊断证据 → 直接干预机制 → 性能恢复/边界。

**最小证据包**：

- 在受控条件下复现失败，并排除数据、实现和规模等简单解释；
- 测量或可视化根因，而不是只报告最终指标；
- 改变该因素后结果按预测方向变化；
- 移除方法中的“根因干预”后收益消失，或出现可解释的边界。

**常见陷阱**：把相关性图当因果证明；用组件消融代替机制干预；把多个可能根因同时写成唯一根因；只在一个数据集上诊断却推广到所有任务。

**写作句式**：

> 在 **C** 条件下，直接控制 **Y** 后出现 **预测 P**；匹配对照 **E** 支持 **Y 参与导致 F** 的解释。

只有实际检验并排除了 **A** 才写“不是 A”。若只有相关性，改为“观察到 Y 与 F 共同变化”，将干预列为待验证动作。

### 2. 反直觉重构（counterintuitive reconstruction）

**核心问题**：领域默认的一个“必须如此”设定是否正好制造了问题？

**典型链条**：共识/默认管线 → 反例或代价 → 替代抽象 → 公平对照 → 更简单或更强的结果。

**最小证据包**：

- 明确写出被挑战的设定以及它为何流行；
- 证明设定带来的具体代价，而不是只宣称“过时”；
- 替代方案在接口、目标或表示层面确实不同；
- 在相同数据、预算和评价协议下做匹配比较，并报告何时替代方案也会失败。

**常见陷阱**：把“换了一个模块”夸成范式革命；只挑有利任务；将反直觉写法当作噱头，缺少可预测机制。

**写作句式**：

> **所引工作** 采用 **设定 A**；我们测得 A 在 **条件 C** 下引入 **代价 B**。替代方案 **D** 在匹配比较中获得 **结果 E**。

### 3. 理论照亮经验（theory illuminating practice）

**核心问题**：能否通过定理、引理、形式化算子或可计算近似，解决一个形式问题或解释经验规律？

**典型链条**：形式问题/经验谜题 → 形式对象与假设 → 定理或界 → 证明、推论与边界；声称解释实践时再连接实证核验。

**最小证据包**：

- 定义清楚对象、假设、量和边界；
- 结论不是把实验结果换成数学符号，而是带来新推论、上界/下界、等价条件或反例；
- 给出构造、证明要点或可复核的推导；
- 说明理论未覆盖的情况；若声称解释经验现象，用相应实验检验理论与实际任务的联系。纯理论贡献不强加实验要求。

**常见陷阱**：声称解释实践却未连接定理假设与实际任务；只证明一个已知事实；把“理论上可能”写成“实践中保证”；用一条曲线代替证明。

**写作句式**：

> 对 **对象 O**，在假设 **H** 下证明 **定理 T**，得到 **界/分离/刻画 Q**。

存在实证结果时再接：“由 T 导出的 **预测 P** 在 **实验范围 R** 内得到支持。”

### 4. 新基准暴露失效（benchmark exposes failure）

**核心问题**：一个重要但模糊的失败，如何变成可复现、可排序、与真实风险对应的测量？

**典型链条**：真实场景/用户痛点 → 现有指标漏测什么 → 任务与数据闭环 → 指标和基线 → 系统性发现 → 后续改进方向。

**最小证据包**：

- 任务定义与真实使用过程之间有可解释映射；
- 数据来源、难例构造、污染检查、标注/模拟用户和工具环境透明；
- 指标衡量的失败与风险或决策后果相关；
- 选择与测量目的有关的强模型、简单基线和参考上界，并报告适用的一致性、不确定性与失败样例；
- 基准不能只靠“更难”成立，要说明它测到了不同维度。

**常见陷阱**：为了让方法排名靠前而设计数据；LLM 评审循环自证；指标与真实价值脱节；只报平均分，不展示错误结构。

**写作句式**：

> 现有评测在 **场景 S** 中看不到 **失败 F**；我们构造 **任务/闭环 B**，让 F 可被 **指标 M** 复现和分解，并发现 **系统性结论 C**。

### 5. 社会价值叙事（social-impact grounding）

**核心问题**：谁受到问题影响，技术在真实约束下能减少什么成本、风险或不平等？

**典型链条**：受影响者/机构 → 现有流程与约束 → 技术介入点 → 泛化、可解释、公平与不确定性 → 可执行影响。

**最小证据包**：

- 具体使用者、受益者和可能受害者，而非抽象的“社会意义”；
- 真实部署约束（地区、语言、资源、隐私、延迟、人工复核）；
- 与部署主张有关的跨群体/跨地点/跨时间验证与误差差异；
- 按使用场景说明不确定性、人工接管和错误代价如何处理；
- 影响声明与实验结果的范围一致。

**常见陷阱**：把高精度等同于社会价值；只展示平均结果；用公益标签掩盖数据权属、偏差或实际不可部署。

**写作句式**：

> 对 **受影响者 G** 而言，当前流程的瓶颈是 **约束 C**；在 **已评估流程 R** 中，系统通过 **介入点 I** 将 **代价 L** 从 **a** 降至 **b**，适用条件为 **B**。

只有模型离线分数时就报告离线结果，把流程成效作为待验证目标，不写成已实现的社会影响。

### 6. 极简统一美学（minimal unification）

**核心问题**：多个任务或现象是否可由同一个接口、表示或原则统一解释，并减少系统复杂度？

**典型链条**：任务碎片化 → 共同结构 → 单一接口/表征 → 多任务预测 → 复杂度、迁移和可解释性收益。

**最小证据包**：

- “统一”发生在问题、表示、训练目标或推理接口中的哪一层；
- 同一组件在不同任务中承担可解释的共同作用；
- 若声称可泛化到新任务，提供留出、组合或迁移测试；已知任务上的共享接口只按已验证范围陈述；
- 报告与“更简单/更省/更快”相对应的参数、训练、推理、数据或维护成本；
- 消融区分“共享原则”与“容量变大/模块变多”的贡献。

**常见陷阱**：把多任务拼接称为统一；一个接口背后仍藏着任务专用分支；只展示收益，不报告复杂度与失败边界。

**写作句式**：

> 原本需要 **N** 个任务专用路径的现象共享结构 **S**；用接口 **U** 查询/表示 S 后，在 **任务集合 T** 上获得 **可复核收益 R**，同时成本变化为 **K**。

## 选主范式，而不是给论文贴满标签

研究定位时可用下面的 0–3 分表比较候选主线，只评与当前贡献有关的维度。它是内部启发式，不是录用预测，也不是局部润色前的必填表；六种都不贴切时直接描述贡献，不强行归类：

| 维度 | 0 分 | 3 分 |
|---|---|---|
| 现象清晰度 | 只有结果差异 | 有稳定、可复现的现象或痛点 |
| 可区分性 | 解释与替代方案无法区分 | 有证据能区分主要替代解释 |
| 证据就绪度 | 只有想法/相关性 | 已有干预、定理、基准或真实约束证据 |
| 迁移价值 | 只适用于一个设置 | 对任务、模型或场景有边界明确的迁移 |
| 叙事压缩度 | 贡献与证据关系难以复述 | 一句话能串起问题、贡献和结果 |

优先选择可区分、证据就绪且有研究价值的主线；分数接近时选择解释力更强、无依据主张更少的那个。辅助范式只用于解释第二层价值，例如“根因手术刀 + 极简统一”或“新基准 + 社会价值”。

## 把范式转成直接的贡献表达

选定主线后，用 [反防御编辑](anti-defensive-writing.md) 把证据写到显著位置。下表的限定应跟随相应主张，不用另起一段笼统道歉。

| 主线 | 优先写出的贡献 | 贴近主张的条件 |
|---|---|---|
| 根因手术刀 | 干预哪个因素，引起了什么可预测变化 | 干预范围、剩余混杂、因果证据等级 |
| 反直觉重构 | 哪个替代设定带来什么收益 | 被比较的实际方案、公平预算、代价 |
| 理论照亮经验 | 证明了哪个界、分离或性质 | 定义、假设、适用对象 |
| 新基准暴露失效 | 测到了什么既有评测漏掉的现象 | 样本构造、测量有效性、模型范围 |
| 社会价值叙事 | 在什么真实约束内改善了什么 | 使用者、流程、实际评估程度 |
| 极简统一美学 | 哪个共享结构覆盖哪些任务 | 任务集合、专用部分、实测成本 |

负结果可以沿用相应主线：例如基准揭示既有增益无法复现。明确研究范围和结果的稳定性，不把“未观测到效果”扩大为“证明效果不存在”。

## 创新层级检查：避免“创新幻觉”

把“新颖”拆成六个问题，避免把工程变化误写成科学发现：

| 层级 | 要问的问题 | 需要的对照 |
|---|---|---|
| 问题 | 是否提出了此前没有被清楚定义的任务/约束？ | 最近任务定义与真实需求 |
| 现象 | 是否发现了稳定、反常或被忽略的行为？ | 多设置复现与负例 |
| 测量 | 是否提供了更能暴露失效的指标/基准？ | 旧指标、污染检查、强基线 |
| 机制 | 是否解释了为什么会发生、何时会消失？ | 干预、反事实、替代解释 |
| 方法 | 是否有与主张直接对应的新算法/表示/证明？ | 简单方法、参数/预算匹配 |
| 系统 | 是否把方法可靠地放进真实流程并降低成本/风险？ | 端到端约束、失败代价、部署基线 |

这些是贡献维度，不是高低排名。只有方法层面的变化，也可以是算法贡献；根据实际新意描述，不自动贬为工程工作，也不暗示机制或理论已经同时被推进。

## 主张—证据对应表

| 主张类型 | 典型措辞 | 最小证据 | 不足以支撑的证据 |
|---|---|---|---|
| 现象主张 | “在 C 下常见失败 F” | 多设置复现、误差分解 | 单个例子、单次运行 |
| 因果主张 | “Y 是 F 的原因” | 受控干预、替代解释排除、恢复/反事实 | 相关性、普通消融 |
| 比较主张 | “比基线更好/更稳/更省” | 公平协议、合适基线、支持该比较的不确定性或成本测量 | 只报最佳数字，以准确率推断效率 |
| 理论主张 | “在 H 下保证/等价” | 定义、证明、边界、推论 | 经验曲线或直觉 |
| 统一主张 | “一个机制覆盖多个任务” | 共享结构和所称任务覆盖；声称迁移或降本时补相应验证 | 只因包装在一个接口中就声称可泛化/更省 |
| 影响主张 | “改善真实流程/公平性” | 受影响者、约束、错误代价、跨群体结果 | 仅模型分数 |
| 负结果主张 | “在 C 下未发现稳定收益” | 清楚范围、可靠对照、重复与不确定性 | 以均值接近零证明等效或普遍无效 |

## 一页主张卡

研究定位或规划实验时可填写；无需凑满三条主张，也不把此卡附在每次改稿之后：

```text
问题/现象/约束：
相关解释、默认设定或形式问题：
主范式：                  辅助范式：
核心主张 C1：
其他独立主张（如有）：
每条主张的当前证据与来源位置：
可区分预测或待证明命题：
最小决定性实验/证明：
最危险的替代解释：
适用边界和已知失败：
目前证据级别：F / I / P / U
```
