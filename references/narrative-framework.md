# 六大叙事范式与研究论证框架

六大范式不是论文类型，也不是投稿模板。它们回答的是六种不同的“研究价值从哪里来”：机制解释、默认设定的重构、形式化保证、失效的测量、真实世界的约束、以及统一性与简洁性。一篇论文可以有多个标签，但应有一条主线能把问题、方法和证据串起来。

## 先画一张故事图

把论文压缩成下面这条有向图；每个箭头都应能在正文中找到证据或明确的假设：

```text
观察到的现象/痛点
        ↓
现有解释或默认设定为何不足
        ↓
可区分的研究问题与假设
        ↓
根因定位、形式化或测量设计
        ↓
方法/基准/理论/系统干预
        ↓
可证伪预测（如果故事为真，哪些结果应出现）
        ↓
诊断、对照、压力测试与主结果
        ↓
适用边界、失败案例、成本与影响
```

“我们提出一个模块，指标提升了”只覆盖了最后两格，通常不足以构成获奖级主张。真正需要判断的是：没有这个模块，哪个现象无法解释；加入它之后，哪个预测被区分出来。

## 六种范式的诊断卡

### 1. 根因手术刀（root-cause scalpel）

**核心问题**：现有方法在什么条件下翻车，真正的限制因素是什么？

**典型链条**：稳定现象 → 机制假设 → 诊断证据 → 直接干预机制 → 性能恢复/边界。

**最小证据包**：

- 在受控条件下复现失败，并排除数据、实现和规模等简单解释；
- 测量或可视化根因，而不是只报告最终指标；
- 改变该因素后结果按预测方向变化；
- 移除方法中的“根因干预”后收益消失，或出现可解释的边界。

**常见陷阱**：把相关性图当因果证明；用组件消融代替机制干预；把多个可能根因同时写成唯一根因；只在一个数据集上诊断。

**写作句式**：

> 在 **C** 条件下，失败并非来自 **常见解释 A**，而是来自 **机制 Y**；当我们直接控制 **Y** 时，**预测 P** 出现，说明 **方法 Z** 的作用点是 **Y**。

### 2. 反直觉重构（counterintuitive reconstruction）

**核心问题**：领域默认的一个“必须如此”设定是否正好制造了问题？

**典型链条**：共识/默认管线 → 反例或代价 → 替代抽象 → 公平对照 → 更简单或更强的结果。

**最小证据包**：

- 明确写出被挑战的设定以及它为何流行；
- 证明设定带来的具体代价，而不是只宣称“过时”；
- 替代方案在接口、目标或表示层面确实不同；
- 在相同数据、预算和评价协议下做匹配比较，并报告何时替代方案也会失败。

**常见陷阱**：把“换了一个模块”夸成范式革命；只挑有利任务；将反直觉写法当作噱头，缺少可预测机制。

**写作句式**：

> 领域把 **A** 当作必要条件，但它引入了 **代价 B**；在保留 **目标 C** 的前提下，改用 **D**，因此得到 **可预测变化 E**。

### 3. 理论照亮经验（theory illuminating practice）

**核心问题**：一个反复出现的经验规律，能否被定理、引理、形式化算子或可计算近似解释？

**典型链条**：经验谜题 → 形式对象/假设 → 定理或界 → 可检验推论 → 实验核验。

**最小证据包**：

- 定义清楚对象、假设、量和边界；
- 结论不是把实验结果换成数学符号，而是带来新推论、上界/下界、等价条件或反例；
- 给出构造、证明要点或可复核的推导；
- 用独立实验检验理论预测，并说明理论未覆盖的情况。

**常见陷阱**：定理假设与实际任务完全脱节；只证明一个已知事实；把“理论上可能”写成“实践中保证”；用一条曲线为宽泛定理背书。

**写作句式**：

> 在假设 **H** 下，量 **Q** 满足 **定理 T**；由此可推出 **经验预测 P**，而 **实验 E** 验证了 P 在 **范围 R** 内成立。

### 4. 新基准暴露失效（benchmark exposes failure）

**核心问题**：一个重要但模糊的失败，如何变成可复现、可排序、与真实风险对应的测量？

**典型链条**：真实场景/用户痛点 → 现有指标漏测什么 → 任务与数据闭环 → 指标和基线 → 系统性发现 → 后续改进方向。

**最小证据包**：

- 任务定义与真实使用过程之间有可解释映射；
- 数据来源、难例构造、污染检查、标注/模拟用户和工具环境透明；
- 指标衡量的失败与风险或决策后果相关；
- 与强模型、简单基线和随机/上界对照，并报告一致性、方差与失败样例；
- 基准不能只靠“更难”成立，要说明它测到了不同维度。

**常见陷阱**：为了让方法排名靠前而设计数据；LLM 评审循环自证；指标与真实价值脱节；只报平均分，不展示错误结构。

**写作句式**：

> 现有评测在 **场景 S** 中看不到 **失败 F**；我们构造 **任务/闭环 B**，让 F 可被 **指标 M** 复现和分解，并发现 **系统性结论 C**。

### 5. 社会价值叙事（social-impact grounding）

**核心问题**：谁受到问题影响，技术在真实约束下能减少什么成本、风险或不平等？

**典型链条**：受影响者/机构 → 现有流程与约束 → 技术介入点 → 泛化、可解释、公平与不确定性 → 可执行影响。

**最小证据包**：

- 具体使用者、受益者和可能受害者，而非抽象的“社会意义”；
- 真实部署约束（地区、语言、资源、隐私、延迟、人工复核）；
- 跨群体/跨地点/跨时间的泛化与误差差异；
- 不确定性、拒答、人工接管和错误代价的处理；
- 影响声明与实验结果的范围一致。

**常见陷阱**：把高精度等同于社会价值；只展示平均结果；用公益标签掩盖数据权属、偏差或实际不可部署。

**写作句式**：

> 对 **受影响者 G** 而言，当前流程的瓶颈是 **约束 C**；系统在 **介入点 I** 降低 **可量化代价 L**，但在 **边界 B** 仍需 **人工/政策措施 H**。

### 6. 极简统一美学（minimal unification）

**核心问题**：多个任务或现象是否可由同一个接口、表示或原则统一解释，并减少系统复杂度？

**典型链条**：任务碎片化 → 共同结构 → 单一接口/表征 → 多任务预测 → 复杂度、迁移和可解释性收益。

**最小证据包**：

- “统一”发生在问题、表示、训练目标或推理接口中的哪一层；
- 同一组件在不同任务中承担可解释的共同作用；
- 任务之间有留出、组合或迁移测试，而不是只在同一数据上多头输出；
- 报告参数、训练、推理、数据和维护成本；
- 消融区分“共享原则”与“容量变大/模块变多”的贡献。

**常见陷阱**：把多任务拼接称为统一；一个接口背后仍藏着任务专用分支；只展示收益，不报告复杂度与失败边界。

**写作句式**：

> 原本需要 **N** 个任务专用路径的现象共享结构 **S**；用接口 **U** 查询/表示 S 后，在 **任务集合 T** 上获得 **可复核收益 R**，同时成本变化为 **K**。

## 选主范式，而不是给论文贴满标签

对每个候选范式按 0–3 分打分：

| 维度 | 0 分 | 3 分 |
|---|---|---|
| 现象清晰度 | 只有结果差异 | 有稳定、可复现的现象或痛点 |
| 可区分性 | 任何方法都能解释 | 只有该范式能给出明确预测 |
| 证据就绪度 | 只有想法/相关性 | 已有干预、定理、基准或真实约束证据 |
| 迁移价值 | 只适用于一个设置 | 对任务、模型或场景有边界明确的迁移 |
| 叙事压缩度 | 需要大量模块和例外 | 一句话能串起问题、方法和结果 |

优先选择“可区分性 + 证据就绪度”最高的范式；若分数接近，选择能减少主张数量、实验负担和评审疑虑的那个。辅助范式只用于解释第二层价值，例如“根因手术刀 + 极简统一”或“新基准 + 社会价值”。

## 创新层级检查：避免“创新幻觉”

把“新颖”拆成六个问题，避免把工程变化误写成科学发现：

| 层级 | 要问的问题 | 需要的对照 |
|---|---|---|
| 问题 | 是否提出了此前没有被清楚定义的任务/约束？ | 最近任务定义与真实需求 |
| 现象 | 是否发现了稳定、反常或被忽略的行为？ | 多设置复现与负例 |
| 测量 | 是否提供了更能暴露失效的指标/基准？ | 旧指标、污染检查、强基线 |
| 机制 | 是否解释了为什么会发生、何时会消失？ | 干预、反事实、替代解释 |
| 方法 | 是否有与主张直接对应的新算法/表示/证明？ | 简单方法、参数/预算匹配 |
| 系统 | 是否把方法可靠地放进真实流程并降低成本/风险？ | 端到端约束、失败代价、部署基线 |

如果只有“方法”一行发生变化，贡献仍可能有价值，但应使用与证据匹配的措辞（例如“有效的工程方案”），不要暗示问题、机制或理论也同时被推进。

## 主张—证据对应表

| 主张类型 | 典型措辞 | 最小证据 | 不足以支撑的证据 |
|---|---|---|---|
| 现象主张 | “在 C 下常见失败 F” | 多设置复现、误差分解 | 单个例子、单次运行 |
| 因果主张 | “Y 是 F 的原因” | 受控干预、替代解释排除、恢复/反事实 | 相关性、普通消融 |
| 比较主张 | “比基线更好/更稳/更省” | 公平协议、强基线、方差和成本 | 只报最佳数字 |
| 理论主张 | “在 H 下保证/等价” | 定义、证明、边界、推论 | 经验曲线或直觉 |
| 统一主张 | “一个机制覆盖多个任务” | 留出任务、组合/迁移、复杂度分析 | 同数据多头输出 |
| 影响主张 | “改善真实流程/公平性” | 受影响者、约束、错误代价、跨群体结果 | 仅模型分数 |

## 一页主张卡

写作或实验前先填完这张卡：

```text
现象/痛点：
被挑战的解释或默认设定：
主范式：                  辅助范式：
主张 C1（必须成立）：
主张 C2（机制/理论/基准）：
主张 C3（比较/影响/迁移）：
每条主张的可证伪预测：
最小决定性实验：
最危险的替代解释：
适用边界和已知失败：
目前证据级别：F / I / P / U
```
