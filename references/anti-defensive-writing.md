# 反防御学术编辑

改编自 Adkid-Zephyr 的 Anti-Defensive Writing（MIT，Copyright (c) 2026 Adkid-Zephyr）。[来源与调整](upstream-integration.md) · [MIT 原文](../licenses/anti-defensive-writing-MIT.txt)。本文件把贡献聚焦与主张—证据核对结合，用于写作、改稿、压缩和 rebuttal。

## 先区分语气与事实

审查一句话时，先问它增加了什么信息，再决定改动。`only`、`limited`、`may`、`under` 本身不是问题；机械删词会同时删掉资源优势、适用范围或真实不确定性。

| 句子的功能 | 例子 | 处理 |
|---|---|---|
| 情绪或作者自评 | “Unfortunately, we must admit…” | 删除开场自评，直接给事实 |
| 无边界的负面判断 | “The method has severe limitations.” | 若材料只支持某一条件下失败，写清该条件和观测；没有依据则删除判断 |
| 定义/理论成立条件 | “Under bounded noise…” | 保留在定理或结论同句/相邻句 |
| 实测损失或反例 | “Accuracy decreases from 84% to 82%.” | 保留具体值与比较条件，可与成本收益并列 |
| 证据不足以确定机制 | “These results may reflect…” | 有相关性时保持推断语气；无法支持该解释时删除解释或列为假设 |
| 量化资源或评价范围 | “only 1% of parameters”; “English-only” | 保留信息，不因出现 only 就改成无范围的结论 |
| 未做的工作 | “Cross-domain transfer has not been evaluated.” | 若影响当前主张，保留；不自动扩写成一段泛化自我否定 |

反防御编辑不要求把每个负面句改成正面句。重复实验显示某策略无效，本身也可能是重要结果；它需要清晰范围、可靠证据和直接表达。

## 从“发现优势”到“写出优势”

1. **定位具体价值。** 从材料选一条可核对贡献：低预算运行、明确失败模式、形式化保证、有效测量、约束内的改进或有用负结果。
2. **核查成立条件。** 对应数据、基线、预算、假设与不确定性都要能找到。仅有均值不能推出统计显著；仅有准确率不能推出效率。
3. **安排论证。** 先说研究问题与本文动作，再用最有解释力的结果支持。开发时间线只在解释关键设计选择时保留。
4. **调整语气。** 用可验证动词替代自我评价和宣传词。删除未提出问题的预防性道歉，也删除没有支撑的“突破性”“全面领先”。
5. **复核语义。** 逐项对照改前改后，检查是否暗中扩大样本、范围、因果性、完成状态或收益。

研究阶段可以据探索结果重设问题，但不能让事后选中的指标看起来像预先确定的主指标。记录焦点调整及选择理由，保留原评价结果，用新数据或预定协议再验证需要确认的主张。

## 内容去留：按论证职责决策

| 内容 | 一般位置 | 不宜做的改动 |
|---|---|---|
| 核心贡献及最有辨识力的证据 | 摘要、引言、主结果 | 留给读者从十张表自行推断 |
| 改变主张真值的失败、成本、假设、不确定性 | 与该主张相邻的正文；摘要作相应限缩 | 放到附录后仍在摘要宣称普适/无损 |
| 强基线、评价口径、影响比较的预算差异 | 实验设置或相关主表/图注 | 为排名更好删除基线或省略不等预算 |
| 机制验证、替代解释、边界诊断 | 支撑相应主张的小节 | 因结果不利而判成“没有论证职责” |
| 重复结果、完整超参、长推导 | 对应附录并在正文指向 | 移走唯一支撑核心结论的证据 |
| 与结论无关的开发流水账、重复道歉 | 删除或压缩 | 把选择偏差的记录也当开发历史删掉 |

每个实验可承担：测量主效果、辨认机制、证明约束内价值、排除替代解释、**发现失败边界或推翻原假设**。只保留能“证明成功”的实验会使这个框架失效。

## 常见改写动作

以下措辞供选择，不是必须套用的模板。完整事实条件见 [改写实例](../examples/before-after.md)。

| 模式 | 改写动作 | 注意 |
|---|---|---|
| “虽然提高了，但我们必须承认……” | 先写具体结果，随后一句写未覆盖范围 | 未覆盖不等于已失败，两者不可混用 |
| “只有 1.3% 的微小提升” | 明确是相对百分比还是百分点；给原始值、波动和条件 | 未提供分母时不擅自算百分比，不自动写 significant |
| “我们先尝试 A，之后改 B” | 按设计目的写 B 的动作，再接已有证据 | 设计意图不能改写成已验证根因 |
| “不如最强方法，因此价值有限” | 精确写评价维度；若有成本收益同时给出 | 没有成本测量时不能补一个效率故事 |
| “没有超过 baseline，但这并不说明无效” | 写明具体比较结果及它允许的结论 | 不用“不同目标”回避原来确实声称的优势 |
| “我们的方法适用于所有……” | 将范围写成已验证的任务、模型、语言或假设 | 不能只在 limitations 里留下反例 |
| “更多实验会证明……” | 写拟检验的问题和执行状态 | 未运行不能写“结果表明” |

百分比示例：从 82% 到 84% 是 **提高 2 个百分点**，相对变化约 2.44%；二者不可互换。没有统计检验或合适区间时，直接写变化值，不使用“统计显著”。

## 各章节的落点

- **摘要**：尽早给问题、动作和已有结果。会改变结果解读的约束跟着结果出现，不强制最后补一条泛泛的不足。
- **引言**：选择一个真实、可核对的缺口。不能为了“反直觉”把领域习惯虚构成人人信奉的共识。
- **贡献列表**：每条写产物或发现及其证据范围；“做了大量实验”通常只是工作量描述。
- **实验**：小节围绕待回答的问题组织。展示目标价值时保留必要对照和反例，而不均分篇幅给所有尝试。
- **结论**：重申已经建立的贡献和意义；可以简洁保留适用条件，不引入新的数字、优势或笼统自我否定。
- **限制**：用户要求时直接写具体限制与影响；按会议要求保留该节，不为“积极语气”挪走必要事实。
- **rebuttal**：先回答实际质疑，再给证据和修订状态。不展开没人提出的问题；也不以“比较不是重点”躲开有效质疑。

## 改动幅度与输出

| 请求 | 改动范围 | 输出方式 |
|---|---|---|
| 最小改动、保留口吻 | 仅改有问题的句子，保留段序、术语和引用 | 改稿；用户要批注时给简短对照 |
| 重写摘要/引言 | 可重排给定事实，压缩重复背景 | 完整成稿；仅说明影响主张的选择 |
| 重构故事 | 可更换主线和贡献顺序 | 新定位及成稿/结构；说明原主张如何修正 |
| 压到 N 词/字 | 优先砍重复和流水账，保留支持主张的必要信息 | 压缩稿与实际计数；遵守用户指定计数口径 |
| 只要英文/LaTeX 正文 | 无额外中文说明、F/I/P 标签或评审清单 | 可直接粘贴的正文 |

压缩时若约束会改变结论理解，就连同主张一起缩短；不能只删约束以满足字数。对 LaTeX 保留 `\cite{...}`、`\ref{...}`、公式、标签名和数值定义。没有问题的段落不必强行改写。

## 编辑前后核对

核对实体、数字、单位、方向、统计量、评价范围、假设、引用和动作状态。凡“更强、更便宜、更稳、机制解释、泛化、显著、相当”的新增含义，均回到账本检查。找到缺证据的地方时，修改该处或说明待补动作，不给整篇机械追加免责声明。
